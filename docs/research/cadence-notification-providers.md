# Cadence in-app Inbox: provider evidence

Research date: **2026-11-17**. Official documentation and public pricing checked on that date; prices are published USD monthly figures, not a quote or a Cadence cost estimate. No budget, delivery volume, retention duration, or residency requirement has been specified. No provider is selected.

Context: [Investigate third-party services for Cadence’s in-app Inbox](https://github.com/Bearded-Productions/ai_hero_training/issues/3), within [Find the way to Cadence’s in-app notification spec](https://github.com/Bearded-Productions/ai_hero_training/issues/1). This is a throwaway research artifact, not an implementation or a procurement decision.

## Scope and conclusion

Compare Knock, Novu Cloud, and MagicBell for persistent React/TypeScript in-app notifications with read/unread state and links to activity. Existing Postmark email stays unchanged. Candidate events are lesson questions/replies, Refund Request updates, and Seat claims, across Students, Instructors, Team Admins, and Platform Admins. Candidates are not committed first-release scope.

All three document hosted Inbox capabilities and a React integration. The consequential differences found are retention, production identity setup, cost units, and development isolation. Knock explicitly retains feed items indefinitely; Novu documents 30/90-day plan limits; MagicBell's reviewed public material does not establish a retention duration. The evidence below supports a selection conversation, not a ranking. [Knock feed retention](https://docs.knock.app/manage-your-account/data-retention), [Novu limits](https://docs.novu.co/platform/developer/limits), [MagicBell React Inbox](https://www.magicbell.com/docs/libraries/magicbell-react).

## Retries, duplicates, and delivery evidence

- **Knock:** workflow trigger supports `Idempotency-Key` with a 24-hour replay window and matching-parameter checks. The reviewed API reference says only the workflow trigger endpoint supports this header. It protects retries within that window, not indefinite deduplication of domain events. Exact recovery behavior after internal in-app creation failure remains to validate. [API reference](https://docs.knock.app/api-reference/overview/api-keys).
- **Novu:** `Idempotency-Key` supports API-key-authenticated POST/PATCH requests, with a 24-hour success/error cache and a five-minute in-progress entry. The feature is **not enabled for every organization**; docs direct customers to support. Concurrent duplicates return 409. `transactionId` is checked later and does not provide the same billing protection. [Idempotency](https://docs.novu.co/api-reference/idempotency). Inbox messages are stored in Novu and pushed over WebSocket; there is no external provider send to retry for Inbox. Do not infer Inbox guarantees from email/SMS retry behavior. [Delivery retries](https://docs.novu.co/platform/developer/delivery-retries).
- **MagicBell:** supported endpoints accept `Idempotency-Key` and cache the first response for 24 hours. The API publishes 500 requests/minute per IP, with 429 on exceeding it. Confirm supported operation coverage for the selected broadcast/client version. Marketing mentions delivery retries, but the reviewed pages do not establish an in-app retry schedule or exactly-once guarantee. [API](https://www.magicbell.com/docs/api), [Inbox service](https://www.magicbell.com/inbox).

**Integration inference:** Cadence still needs a policy for committed application events whose notification trigger times out or fails. A stable event identifier, persisted dispatch status, retry policy, and deduplication beyond vendor cache windows may be needed. None of these docs establishes an atomic transaction spanning Cadence's database and a vendor. Whether an outbox is warranted is an operational/spec decision, not resolved here.

## Data handling

- **Knock:** vendor states encryption at rest, TLS 1.2 for cross-service traffic, and SOC 2 Type 2 compliance. Its security page says EU residency is coming by end of 2026, so do not treat EU hosting as available today. Subprocessor list includes AWS in the USA. [Security](https://docs.knock.app/developer-tools/security), [subprocessors](https://knock.app/legal/subprocessors). Feed responses can expose actor/recipient custom properties and trigger payload; configure response filtering and send minimal data. [Feed response filtering](https://docs.knock.app/integrations/in-app/feeds).
- **Novu:** US (Virginia) and EU (Frankfurt) residency are documented, with additional Enterprise regions; region-specific keys/endpoints apply. Vendor provides DPA/SCC material and documents message/log retention separately; specific deletion inquiries go to support. Confirm the selected region and deletion/export procedures before provisioning. [Security and residency](https://docs.novu.co/platform/additional-resources/security).
- **MagicBell:** vendor security page states encryption in transit/at rest and DPA/data-portability support. Reviewed material does not establish the hosting region, precise customer-message retention, backup deletion timing or a current subprocessor inventory. Request these details if they affect selection; do not equate general security marketing with a deployment commitment. [Security](https://www.magicbell.com/security).

These are vendor statements, not an independent security audit. Cadence's required fields and retention still need a product decision. In-app-only delivery can use stable internal user IDs and minimal event summaries; there is no reason in this scope to migrate Postmark credentials or send full Refund Request records to the Inbox vendor (integration recommendation).

## Implications and unresolved selection questions

1. **History duration:** Is 30 or 90 days acceptable, or must notifications remain until explicitly removed? This directly affects Novu plan suitability and requires MagicBell clarification.
2. **Recipient rules:** Which candidate events and roles ship first? Cadence must select authorized recipients from current application relationships, rather than assuming vendor tenant/context fields implement course or Team permissions.
3. **Identity and changing access:** Issue Inbox credentials only from the authenticated server session. Clear/reinitialize client state on sign-out, DevUI user changes, and tenant changes. Check destination authorization again when following links; decide what to show for deleted or inaccessible activity. These are proposed acceptance checks, not verified application behavior.
4. **Cost inputs:** Expected events, recipients per event, monthly fan-out, environment count, acceptable branding, retention and budget are required before a cost comparison. No provider is cheapest for Cadence on the evidence available.
5. **UI integration:** Validate the chosen SDK against the repository's actual React Router/React versions, SSR/hydration boundary, navigation, keyboard access, unread badge behavior and styling. This research did not install packages, provision accounts, execute a delivery test, or assert production compatibility.
6. **Operations:** Decide delivery latency/failure expectations, retry ownership and duplicate behavior. Confirm Novu idempotency enablement; MagicBell retention/environment/retry details; Knock in-app failure recovery and any required residency offering.
7. **Data lifecycle:** Decide what summaries may leave Cadence, retention/deletion on account closure, export requirements and handling of permissions revoked after delivery. Vendor storage should not become the authoritative record of Refund Requests or Seat claims.

Research is sufficient to discuss provider choice. Missing vendor commitments and live integration checks are recorded explicitly; the human selection and experience tickets remain open.
